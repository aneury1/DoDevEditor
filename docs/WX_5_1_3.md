# DoDevEditor wxWidgets 5.1.3 — Runtime path and toolbar tasks

Based on 5.1.2. Existing menus, themes, workspace tools, task parser, and Remote Journal SSH password mode remain intact.

## Install-time runtime library search path (Linux)

`cmake/WxRuntimePath.cmake` sets `BUILD_RPATH` and `INSTALL_RPATH` on `DoDevEditor` using the directories discovered by FindwxWidgets (also extracts `-L` flags and absolute library paths). `INSTALL_RPATH_USE_LINK_PATH` is enabled. This preserves custom wxWidgets installations such as `/usr/local/lib` without hardcoding that path. CMake displays the discovered directories during configuration. This does not install missing libraries, repair missing SONAME symlinks or resolve every indirect dependency: if necessary use `ldconfig` for system-wide shared library lookup.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/usr/local
cmake --build build -j$(nproc)
sudo cmake --install build
readelf -d /usr/local/bin/DoDevEditor | grep -E 'RPATH|RUNPATH'
ldd /usr/local/bin/DoDevEditor | grep 'not found'
/usr/local/bin/dodeveditor --foreground .
```

## Task toolbar

The theme selector is followed by a task dropdown and a **Run Task** button. The workspace `.vscode/tasks.json` is preferred, with the existing global settings-directory `tasks.json` fallback only when the workspace file is missing. The existing JSONC parser is shared by the toolbar and Terminal menu. The default build task is initially selected (otherwise the first task). Selection is retained by label on refresh within the same workspace. Changing workspaces resets selection. Saving `tasks.json` triggers immediate reload; external modifications, creation and deletion are detected by a one-second metadata poll (mtime and size). Configure Tasks also refreshes the list. Invalid configurations clear the list and disable Run Task; the tooltip gives the parser error. The Terminal menu remains available for explicit error dialogs.

Selecting a task alone never executes commands. Clicking Run Task reloads and validates the current configuration, resolves the exact selected label, plans dependencies, asks for workspace trust, and opens the existing task terminal. The execution and error handling follow the 5.1.2 task runner. Unsupported extension task types/background tasks/parallel dependencies still produce the existing validation errors. No new claims of VSCode feature parity are made.

## Validation

Targeted Debug CTest checks: workspace_task_catalog, vscode_terminal_tasks, wx_install_runtime_path, wx_raven_menu_parity (4/4 passed). The runtime-path test installs a real Linux executable linked to a fixture shared library in a nonstandard directory containing spaces, and executes it without LD_LIBRARY_PATH. It is not a native wxWidgets integration test. No wxWidgets headers/libraries are installed in the test environment; GUI compilation, actual wx runtime loading and interactive toolbar behavior remain unverified. The poll uses metadata; saving internally and explicit execution always force a reparse. No full inherited test suite was rerun for this release.
