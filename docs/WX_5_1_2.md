# DoDevEditor wxWidgets 5.1.2 — VSCode tasks and SSH password authentication

## VSCode tasks

Terminal > Run Task and Run Build Task (Ctrl+Shift+R and Ctrl+Shift+B by default) read `.vscode/tasks.json` in the workspace, or the settings directory task file only when the workspace file does not exist. Configure Tasks opens/creates the workspace file. Save the file before running a task. Malformed workspace files are reported, not silently replaced with another configuration.

Supported: JSONC comments/trailing commas/BOM, shell/process and explicit cppbuild commands, args, options.cwd, POSIX options.env, options.shell.executable and args, platform overrides, default build group, dependsOn (single or ordered sequence), commandless compound tasks, cycle detection, and common VSCode variables (workspaceFolder, workspaceFolderBasename, cwd, file, fileDirname, fileBasename, fileBasenameNoExtension, fileExtname, relativeFile, relativeFileDirname, lineNumber, columnNumber, selectedText, userHome, env:NAME, pathSeparator). Each task plan uses a separate PTY/ConPTY tab and an argument vector for process tasks; shell tasks use /bin/sh -c on POSIX by default. Task sequence progression checks process exit status; failures cancel remaining tasks. Close via Terminal > Close. Each launch requires approval because project tasks execute arbitrary commands. Shell commands with no args are shell source; quote substituted paths appropriately or use process tasks. Copy `examples/vscode-tasks/.vscode/tasks.json` into an existing CMake project.

Not implemented: parallel dependencies, background/watch-task readiness, problem matcher diagnostics, presentation options, input/command variables, multi-root named variables, VSCode extension task providers, object-form quoting, and full Windows shell-specific escaping/environment support. GDB preLaunchTask still uses the previous independent parser. POSIX environment overrides use `env`, so avoid placing secrets in tasks.json (they may appear in process arguments). GUI/native runtime tests were not possible in this environment.

## Remote Journal

The previous implementation used BatchMode=yes exclusively. The dialog now offers SSH key/agent (default) or SSH password (prompt). Choose the latter and press Start; a masked wxPasswordEntryDialog opens. Passwords are sent to `sshpass -d` via an anonymous close-on-exec pipe, not command-line text, settings, exported logs or environment variables. Best-effort clearing of application string storage does not guarantee memory erasure. There is no password persistence. Requires OpenSSH plus sshpass for password mode on POSIX. On CachyOS: `sudo pacman -S --needed openssh sshpass`; Debian/Ubuntu: `sudo apt install openssh-client sshpass`. Password mode selects password/keyboard-interactive authentication, disables public-key auth, and handles a single password prompt, not MFA. Key mode still works without sshpass. Password rejection and missing helper are reported in status. Stop/Start retries prompt anew.

StrictHostKeyChecking=yes is always enforced. For a new host, verify its fingerprint independently and connect once in an ordinary terminal using `ssh -p 22 user@host` to establish known_hosts. Never disable host-key verification to fix this. Remote journal permissions are separate: use an account authorized to read the journal or enable optional `sudo -n` only if remote passwordless sudo is configured. This is not a remote sudo password prompt. Windows journal transport remains unsupported. No real remote host or sshpass installation was available; mock helper and SSH tests cover flags, descriptor delivery, successful streaming and rejected password status.

## Build

`cmake -S . -B build -DCMAKE_BUILD_TYPE=Release` then `cmake --build build -j$(nproc)` and `cmake --install build --prefix "$HOME/.local"`. Headless tests can be built with `-DDODEV_BUILD_GUI=OFF -DCMAKE_BUILD_TYPE=Debug`. Prior explorer/theme changes and Raven menu definitions are retained.
