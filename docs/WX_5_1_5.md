# DoDevEditor wxWidgets 5.1.5 — Launch.json menu

## Run > Launch.json

- **Select Configuration...**: choose a supported cppdbg/GDB profile by name; shares the existing GDB plugin setting. Selection is revalidated against the saved workspace file before execution.
- **Open / Configure launch.json...**: open `.vscode/launch.json` in Scintilla. If absent, offer to create a profile.
- **Add C++ Launch Configuration...**: enter the profile name and program path (including VSCode variables). For an existing JSONC file, ask before replacing comments/formatting; append to an editable buffer with undo support, without writing to disk until Save. Existing JSON values are retained. For a missing file, create it after the two dialogs are accepted.
- **Start Debugging**: same action as F5, using the selected GDB configuration. Existing plugin controls and settings are retained. The plugin must be enabled for its step/breakpoint controls.
- **Run Without Debugging** (`Ctrl+F5`): run the selected local C++ launch profile in an independent terminal. Trust confirmation is required before executing any process.

The original 100 Raven menu entries remain intact. The task toolbar and theme selector are unchanged. The GDB plugin's menu/panel start, select and configure commands use the same native selection flow in wxWidgets. Modified launch.json editor buffers must be saved before selection or run; cancelling aborts.

## Direct launch

Supported: cppdbg / MIMode gdb / request launch, program, args, cwd, POSIX environment, platform overrides, JSONC, preLaunchTask (literal task label or `${defaultBuildTask}`). The existing task dependency runner stops after a failed build. The target executable is checked before its own process starts, so the build may create it. No shell is used to interpret target arguments. Launch input variables use the shared task resolver and a separate input namespace from tasks.json. Input cancellation happens before any task process is started. Each direct launch creates a new terminal; stop/interrupt the session using the existing terminal controls.

The existing task resolver supports `${workspaceFolder}`, `${file}`, `${env:NAME}`, `${config:NAME}`, `${input:ID}` and mapped `${command:ID}` (among others); see WX_5_1_4.md. For direct launch the inputs array is read from launch.json. GDB debug mode continues to use its previous launch-field resolver and preLaunchTask implementation; its interactive pre-launch prompts and extended launch-field variables are not supported yet. Direct launch rejects attach, remote GDB, external consoles, core dumps and postDebugTask. Windows environment handling has the existing task-runner limitation. Working directories must exist at planning time. Extension debug adapters, compounds and full DAP/MI2 are not implemented. Profile selection persists in existing GDB plugin settings, not a per-workspace database; if the name is absent in another workspace, the picker opens again.

## Example

Open `examples/launch-profiles` as a workspace on Linux. Run > Launch.json > Select Configuration, then F5 or Ctrl+F5. The example uses static build tasks so both launch paths can work. Build with debug symbols for GDB.
