# Call Hierarchy (4.3.0)
Open a workspace and allow the background symbol index to finish. In Symbols select a function or method and click Call Hierarchy. Alternatively open Call Hierarchy from the View menu and enter an exact symbol name. Switch Incoming/Outgoing, adjust depth (1–15, default 5), double-click a row to navigate, or use the selected row as root. Export DOT saves the displayed hierarchy; render with `dot -Tsvg call-hierarchy.dot -o call-hierarchy.svg`.

Call data is stored alongside symbols in `.dodev/symbols-cache.json` (schema 2). The first scan upgrades the old cache by rebuilding once; unchanged files subsequently reuse both symbols and calls. Files changed, added or deleted are reflected on the next workspace scan. Clang direct call extraction reuses the existing AST, with lexical C/C++ fallback. Cross-file matching is name-based, not a full compiler USR index; overloaded or duplicate targets may be ambiguous. Indirect calls, templates, macros, constructors and virtual dispatch are not comprehensively resolved. The existing Clang invocation does not consume compile_commands.json. Incoming results are inferred and may include same-name callers. The hierarchy is an indented table with a depth limit and 2000-row cap, not a native expandable tree. No runtime tracing or sequence diagram export is included. Full Raven GUI runtime has not been verified.

Headless test: `cmake -S . -B build-test -DDODEV_BUILD_GUI=OFF -DDODEV_BUILD_QRCODE_PLUGIN=OFF && cmake --build build-test --target dodev_symbols_tests && ctest --test-dir build-test -R source_symbols_outline_csv --output-on-failure`.
