# DoDevEditor wxWidgets 5.1.1

## Explorer

- Explicitly enumerate the root before calling `Expand()`. A tree item without children or an expansion indicator may not generate an expanding event.
- On expanding a directory, enumerate its immediate children once; do not delete/recreate them on each expand. Refresh rescans materialized branches and restores expanded paths and selection where still present.
- Display all immediate filesystem entries, including extensionless files and hidden files by default, with no arbitrary listing cap. Directory entries appear before files. Deep descendants are loaded on demand, not eagerly.
- Show a readable error row if enumeration fails. Broken links remain visible. Symlinked workspace roots work; internal directory links can expand unless they lead back to an ancestor. External directory links and recursive links remain visible but are deliberately not followed. This avoids traversal and destructive operations outside the intended project through the explorer.
- Workspace navigation does not alter the workspace root used by GDB and source indexing. Expand/collapse, context menus and Reveal in Explorer share the same lazy loading logic.
- Refresh is manual; filesystem watcher support is not added in this release.

## Themes

All 13 Raven palettes and custom themes are retained. The theme applies to wxWindows recursively, including Scintilla, data views, trees, lists, text inputs, buttons, status bars, toolbars, notebook pages and AUI docks. Selection text is chosen for contrast. Modal dialogs pass through the common theme application path; existing open dialogs and newly created terminal panels are also updated.

For wxGTK3 on Linux, CMake discovers GTK3 using pkg-config and adds an application-local CSS provider. GTK menus, notebook tabs, buttons, text fields, popovers, tooltips, scrollbars and native dialog widgets inherit the current palette. No OS configuration files are changed. The GTK preferred dark setting is process-local. Transparent effects remain opaque. Native AUI tab art, OS decorations, portal dialogs, icons and Windows/macOS system-drawn controls may not match the palette exactly. The GTK path is optional and portable wxWidgets colors remain available without GTK3 development headers.

Arch/CachyOS: `sudo pacman -S --needed wxwidgets-gtk3 gtk3 pkgconf`
Debian/Ubuntu: `sudo apt install libwxgtk3.2-dev libgtk-3-dev pkg-config`

`-DDODEV_WX_GTK_THEME=OFF` disables GTK CSS if necessary.

## Validation

A fresh headless Debug build passed all 37 CTest tests (including the new filesystem regression and menu parity tests). These tests do not establish native GUI or CSS runtime correctness.

The new filesystem regression executable can be built without a display or wxWidgets:

```
cmake -S . -B build-core -DDODEV_BUILD_GUI=OFF
cmake --build build-core --target dodev_wx_explorer_tests
ctest --test-dir build-core -R wx_explorer_filesystem --output-on-failure
python3 tests/test_wx_menu_parity.py
```

Manual GUI smoke test (requires wxWidgets and display):

1. Open a workspace with `.vscode`, deeply nested directories, extensionless files and a directory containing hundreds of files. Confirm the root is immediately visible; expand several branches.
2. Collapse/re-expand, reveal an open file, refresh, and check expansion and selection are restored. Create a new file in a selected directory and refresh. Toggle hidden files and confirm the workspace root is unchanged.
3. Open a workspace through a directory symlink; verify nested internal aliases expand while ancestor/external links stay visible and do not expand.
4. Switch between VS Code Dark Modern, VS Code Light Modern and a custom palette with Settings open. Verify main window, notebook tabs, status bar, controls, dialogs, AUI captions and new terminal tabs. On GTK verify native menu dropdowns and scrollbars; file chooser may use the system theme when using a portal.
5. Confirm GDB, shell commands and Symbols/Calls still work. Check `dodeveditor --version` reports 5.1.1.

Native GUI and GTK CSS runtime testing require installed wxWidgets and GTK3 development libraries, which were not available in the packaging environment.
