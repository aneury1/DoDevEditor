# DoDevEditor 5.2.9 — Windows wxWidgets fallback

## Requirements

CMake >= 3.21, C++17 compiler and Windows SDK (MSVC) or MinGW-w64 compiler and headers. Ninja is required only for Ninja presets. Python is optional for Python regression tests. Fetching wxWidgets does not install a compiler or Windows SDK. Other plugins may still need curl, SQLite, OpenSSL and zlib; their existing optional dependency handling is unchanged.

## Dependency selection

`cmake/WxDependency.cmake` tries the installed Windows config package and then CMake's traditional FindwxWidgets. If no compatible package is detected, Windows defaults to FetchContent. Linux/macOS keep the installed-first policy and do not fetch unless explicitly enabled. `-DDODEV_BUILD_GUI=OFF` bypasses wx entirely.

`cmake/WxFetch.cmake` fetches the complete official wxWidgets 3.2.6 source archive, not the autogenerated GitHub source archive (which lacks submodules). SHA-256 is pinned to `939e5b77ddc5b6092d1d7d29491fe67010a2433cf9b9c0d841ee4d04acb9dce7` (https://lists.freebsd.org/archives/dev-commits-ports-branches/2024-November/008820.html). TLS verification remains enabled. Static wx targets core, base, aui, stc and adv are linked through the existing `dodev_wx_dependencies` target. Samples, tests, demos and optional WebView/media modules are disabled for the fetched dependency. No wx DLL needs to be copied for this static build; compiler runtimes and other DLLs may still be needed. Installed shared wx packages still require their matching runtime DLLs.

## MSVC x64 (Visual Studio 2022)

```powershell
cmake --preset windows-msvc-release
cmake --build --preset windows-msvc-release --parallel 4
ctest --preset windows-msvc-release
cmake --install build-windows-msvc-release --config Release --prefix C:/DoDevEditor
```

Or use the logging script (run from project root):

```powershell
.\scripts\build.ps1 -BuildDir build-msvc -Generator 'Visual Studio 17 2022' -Architecture x64 -Jobs 4
```

## MinGW-w64

Open a PowerShell environment with the chosen MinGW-w64 compiler and Ninja on PATH (do not mix MSYS/Cygwin with native MinGW). Use a new build tree when changing compiler, generator or target architecture.

```powershell
cmake --preset windows-mingw-release
cmake --build --preset windows-mingw-release --parallel 4
```

With the logging script:

```powershell
.\scripts\build.ps1 -BuildDir build-mingw -Generator Ninja -CMakeArgs @('-DCMAKE_C_COMPILER=gcc','-DCMAKE_CXX_COMPILER=g++')
```

## Logs and overrides

The script streams both stdout and stderr to the console and writes `logs/configure.log`, `logs/build.log`, and `logs/tests.log` under the build directory (last run, for each executed stage). `-VerboseBuild` prints full compiler commands; `-SkipTests` omits tests. The script returns a failure if a native stage returns nonzero. On Windows PowerShell, if local policy blocks an unsigned script, review the script then use `Unblock-File .\scripts\build.ps1` where the downloaded-file marker is the cause, or use the direct CMake commands above. Do not change machine-wide execution policy just for this project.

| CMake option | Meaning |
| --- | --- |
| `DODEV_FETCH_WXWIDGETS` | Default ON on Windows, OFF elsewhere. Fetch if installed package unavailable. |
| `DODEV_WX_FORCE_FETCH` | Skip installed lookup; useful for compiler/ABI mismatch or partial config package. |
| `DODEV_WX_FETCH_PROGRESS` | Default ON. Real download progress and extraction messages at configure time. |
| `DODEV_WX_SOURCE_ARCHIVE` | Local complete official 3.2.6 tar.bz2; same checksum verification. |
| `FETCHCONTENT_SOURCE_DIR_WXWIDGETS` | Trusted pre-extracted source directory, with all submodules. Bypasses network and archive hash check. |
| `FETCHCONTENT_BASE_DIR` | Source/build cache location (default `<build>/_deps`). Use short paths on Windows. Do not share build trees across compilers. |

Force a clean source fallback:

```powershell
.\scripts\build.ps1 -BuildDir build-fetched -ForceWxFetch -Jobs 4
```

For an offline archive already downloaded and verified:

```powershell
.\scripts\build.ps1 -BuildDir build-offline -WxSourceArchive C:/deps/wxWidgets-3.2.6.tar.bz2
```

Or use `-DFETCHCONTENT_SOURCE_DIR_WXWIDGETS=C:/deps/wxWidgets-3.2.6` for trusted extracted sources. Archive download, verification and extraction take place during CMake configuration, compilation takes place during `cmake --build`. Reconfiguration in the same build directory reuses the FetchContent cache. If an installed CMake package has already registered incomplete wx targets, configure a fresh directory with `-DDODEV_WX_FORCE_FETCH=ON` to avoid conflicting targets.

## Verification

`ctest -R wx_dependency_fetch --output-on-failure` exercises installed-package selection, local source fallback, disabled-fetch diagnostics, real HTTP download progress against a localhost fixture, SHA-256 mismatch rejection, extraction, compilation/linking of synthetic wx targets and offline cache reuse. It does not compile real wxWidgets or Windows binaries. The release environment could not resolve github.com and has no Windows toolchain or wx headers; native GUI and PowerShell execution remain unverified. For Windows issues send the configure and build logs.
